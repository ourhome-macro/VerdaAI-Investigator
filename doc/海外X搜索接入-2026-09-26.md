# 海外 X 搜索接入

日期：2026-09-26

## 结论

海外竞品的社区舆情需要单独检索 X 帖子。当前 FuturePPO 网关能用现有 Key 调用 Grok 模型，但对 `/v1/responses` 传入 `web_search` 与 `x_search` 后，实测两种工具调用数都为 0、没有结构化引用。因此当前本机配置采用 `GROK_SEARCH_MODE=planner`：Grok 规划 X 定向查询，AnySearch 检索帖子 URL，再抓取原帖正文；不能把它标称为原生 xAI `x_search`。

代码同时提供 `native` 模式的 `x_search` 适配器。只有真实工具调用和结构化 X 帖子 URL 同时存在时才接受结果；不支持时熔断该网关并由结构化搜索回退。

## 路由与证据

- 研究市场字段或原问题明确为海外、全球、美国、欧洲等范围时，社区维度为每个品牌增加一次 `site:x.com` 的定向搜索；其他市场维持原社区搜索路径。
- 仅接收 `x.com`/`twitter.com` 的单帖 `/status/{id}` URL，过滤账号主页和其他网页。X 帖子归类为 `community`，来源类型为 `x`。网页正文抓取成功后才进入 Evidence；后续原子论点仍要逐条核验引用，官方账号宣传不能当作用户口碑。
- 为避免成本失控，每品牌社区维度只触发一次 Grok 补充调用：海外用于 X 定向查询，其他市场用于普通社区补充查询。搜索与正文仍受缓存、TTL 和出站限流保护。

## 验证

- FuturePPO 的 `x_search` 实测：HTTP 200，但 `num_server_side_tools_used=0`、无引用 URL，故未作为原生搜索启用。
- AnySearch X 定向搜索返回真实 `x.com` 帖子 URL。样例 URL 的 AnySearch Extract 与本机正文抓取都返回帖文正文。
- 完整 X 定向路由实测返回 3 条 X URL：1 条来自 AnySearch 原查询，2 条来自 Grok 规划查询后由 AnySearch 检索；全部保留真实 URL 与来源标记。
- 99 个后端测试与前端生产构建通过；后端与 API 两份核心代码保持一致。

资料：[xAI X Search 官方文档](https://docs.x.ai/developers/tools/x-search)、[xAI Web Search 官方文档](https://docs.x.ai/developers/tools/web-search)。
