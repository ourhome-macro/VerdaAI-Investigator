# 三层角色职责与实际编排

日期：2026-09-24

## 一句话

L3 决定研究什么、谁负责、结果能否交付；L2 将证据组织为竞争判断；L1 搜集和整理可追溯的原始证据。

| 层级 | 设计职责 | 主要输入 | 主要输出 |
|---|---|---|---|
| L3 总控/决策层 | 拆解用户需求，确定竞品和维度，动态组队；检查覆盖度、事实支持与风险，决定返工或签发；首席分析官统筹写作 | 用户问题、研究契约、分析结果、质检反馈 | 任务计划、专家指派、返工指令、最终报告 |
| L2 策略层 | 从证据中提炼按品牌×维度的原子事实，形成定价、竞争格局、用户等方面的判断，并接受核验 | L1 的证据原文、研究维度与反馈 | 带来源的论点、结构化分析、策略洞察 |
| L1 执行层 | 按品牌与维度搜索、抓取、去重、归档来源；补采缺失证据，辅助口碑等专项处理 | L3 的采集任务、查询角度与来源约束 | 可追溯的网页证据、来源元数据、采集诊断 |

## 一次任务的走向

`用户需求 → L3 定范围/组队 → L1 采证据 → L2 形成论点并核验 → L3 质检 → 必要时打回 L1/L2 → L3 统筹写作和交付`

## 当前实现的准确边界

这三层是角色与责任划分，实际运行由一个 Python 编排器依次推进阶段，并非 48 个自治 Agent 进程。动态组队只选择本次参与角色；证据采集目前主要由选出的一个 L1 负责人执行，原子分析标记一个 L2 负责人并由线程池处理各品牌×维度单元。章节写作在代码里标记为 L3-002（若未入选则为 lead），不等同于 L2/L1 专家各自独立写作。质检与返工由编排器执行并记录结构化事件。
