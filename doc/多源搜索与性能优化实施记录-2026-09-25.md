# 多源搜索与性能优化实施记录

日期：2026-09-25

## 已落地

- AnySearch `/v1/search`：结构化 URL、标题、摘要接入原证据链；与博查结果按规范化 URL 去重。官方维度优先博查、社区维度优先 AnySearch，结果足够时不再调用另一结构化搜索源，减少重复费用。已通过真实小请求验证。
- Grok `/v1/responses` Web Search 适配器：仅接受真实工具调用产生的结构化来源 URL，随后仍由网页抓取和证据校验决定能否进入报告；没有实际工具调用时熔断该网关，避免把模型回答误作搜索结果。
- FuturePPO Grok 规划模式：复用已有 Grok Key 通过 OpenAI 兼容 `chat/completions` 生成一条补充检索词，实际检索由 AnySearch 执行。社区维度每品牌主搜索只追加一次，避免所有矩阵单元额外调用模型。模型输出的文字和 URL 不直接进入 Evidence。已通过 Grok + AnySearch 的真实串联请求验证。
- 海外市场的社区维度新增 X 帖子专项检索。`native` 模式调用真实 `x_search` 并以结构化帖子 URL 为线索；当前 FuturePPO 的 `planner` 模式会生成 X 定向查询，再用 AnySearch 检索并抓取原帖。X 来源按社区证据分类，仍需正文与逐条观点核验。
- 新增公开 URL 校验，拒绝本机和私网字面 IP，网页抓取的重定向请求也重新检查目标；避免外部搜索结果把采集器引向内网。
- FuturePPO 网关核验：`/v1/models` 包含 `grok-4.7`，普通模型调用成功；但对 `/v1/responses` 传入 `web_search` 后实测 `num_server_side_tools_used=0`、无引用 URL。故本机改用 `SEARCH_PROVIDERS=bocha,anysearch,grok` 与 `GROK_SEARCH_MODE=planner`，无需另一个 xAI Key。只有切换到 `native` 模式才需要支持服务端搜索工具的网关。
- 同一 FuturePPO Key 对 `x_search` 的实测也返回 0 次工具调用和 0 条引用。AnySearch 的 X 定向查询返回真实 `x.com` 帖子 URL；其 Extract 接口和本机正文抓取均能读取样例帖文，但本次不把单条样例当成用户口碑结论。
- 搜索与网页正文分别使用有界 SQLite 缓存，各最多 2000 条，缓存键绑定研究契约版本。搜索结果依时效与内容从 1 小时到最长 7 天；定价查询缩短为 6 小时。网页正文仅缓存成功抓取的原文，按请求的最短 TTL 重新验证年龄，访客之间隔离。失败与占位摘要不缓存。
- 出站请求按提供商/凭据设置进程级令牌桶与在飞上限；429 冷却重试。当前 Compose 单后端实例适用，多实例需共享配额存储。
- 品牌采集改为可配置的有限并行（默认上限 2，代码硬上限 3），每个品牌单独维护 URL 去重范围；返工继续沿用整任务证据 URL 集合。
- 模型输入添加 UTF-8 字节预算；记录每次模型真实输入、输出及提供商缓存命中 Token。字节预算是本地保护阈值，不是假称的精确模型 Token 计数。
- `performance` 随报告及每次运行尝试保存阶段时长、搜索/抓取/模型调用耗时样本、缓存命中与 Token；失败尝试也纳入耗时分布。`GET /api/performance` 对最近可访问运行汇总 P50/P95、失败次数、返工次数和总用量。

## 本次验证

- 99 个后端单元测试通过，覆盖 AnySearch 结果归一化、海外 X 定向路由与正文入库、FuturePPO Grok 查询规划、Grok 虚假原生 Web/X 搜索熔断、URL 来源约束、私网目标阻断、缓存时效、并发限额、两品牌并行上限、跨报告 P50/P95、模型超大输入预拒绝及既有证据链回归。前端生产构建通过。
- AnySearch 真实 API 返回两条结构化网页结果；再次调用命中本地持久缓存，无网络请求。社区搜索真实串联验证返回 2 条 AnySearch 原检索结果和 2 条 Grok 规划查询后由 AnySearch 找到的新 URL。
- `GET /api/performance` 返回 200 和预期汇总字段；后端与 API 镜像的核心实现保持一致。

## 后续约束

- FuturePPO 提供的 Key 能用于 Grok 规划检索词，由 AnySearch 做实时搜索；该网关当前不能承担 `native` Grok Web Search。切换 `GROK_SEARCH_MODE=native` 前，应确认服务端搜索调用和结构化引用 URL 均真实返回。
- 当前缓存与限流均适合单实例 Compose。多实例部署前把限流状态迁移到共享原子存储；SQLite 缓存仍可在单机共享卷使用，跨主机需换共享缓存。
- P50/P95 需要多份真实报告样本才有统计意义。本次没有执行完整在线 5×6 调研，因此不能宣称端到端提速百分比。
